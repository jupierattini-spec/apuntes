Agenda

Lo que veremos

Para empezar

Qué es MPLS y qué problema resuelve

MPLS (Multiprotocol Label Switching) es una técnica de reenvío que usan los proveedores de servicio en su núcleo. En lugar de que cada router decida mirando la IP de destino, el paquete recibe una etiqueta al entrar a la red y los routers siguientes deciden solo con esa etiqueta.

Enrutamiento IP tradicional

Cada router decide desde cero

  • Cada salto busca la IP de destino en su tabla con coincidencia más larga (longest match).
  • La decisión depende solo del destino: es difícil separar clientes o forzar un camino distinto.
  • Todos los routers del núcleo deben conocer todas las rutas, incluidas las de los clientes.
Con MPLS

Se clasifica una vez, se conmuta muchas

  • El router de borde mira la IP una sola vez, decide a qué grupo pertenece el paquete (FEC) y le pone una etiqueta.
  • El núcleo solo lee la etiqueta: busca una coincidencia exacta y la cambia por otra.
  • El núcleo no necesita conocer las rutas de los clientes. Encima se construyen VPN de capa 3, de capa 2 e ingeniería de tráfico.
Analogía: en un aeropuerto, el mostrador lee tu pasaje una vez y pega una etiqueta en la maleta. Las cintas y los operarios ya no leen el pasaje: solo miran la etiqueta para saber a qué cinta va. El router de borde es el mostrador; el núcleo MPLS son las cintas.
La idea en movimiento

Reenviar por etiqueta en vez de por dirección IP

MPLS (Multiprotocol Label Switching) decide el reenvío con una etiqueta corta. Solo los routers de borde miran la IP; el núcleo cambia una etiqueta por otra.

Qué aporta

  • Menos trabajo en el núcleo: buscar una etiqueta es más simple que buscar el prefijo más largo.
  • Independiente del protocolo de capa 3: sirve para IPv4, IPv6 y tramas de capa 2.
  • Es la base de las VPN de capa 3, las de capa 2 y la ingeniería de tráfico.
MPLS no es mucho más rápido que el enrutamiento IP actual con CEF. Su valor está en los servicios que permite construir encima.

Los términos que vas a ver en toda la unidad

Cada uno se desarrolla en las diapositivas siguientes. Este es el mapa para no perderse.

TérminoQué es
Etiqueta (label)Número de 20 bits con significado local entre dos routers vecinos. Va dentro de una cabecera de 32 bits.
FECForwarding Equivalence Class: grupo de paquetes que se tratan igual (normalmente, los que van al mismo prefijo). Cada FEC recibe una etiqueta.
LSRLabel Switching Router: cualquier router que entiende etiquetas MPLS.

LSR intermedio / PRouter del núcleo (Provider). Solo cambia etiquetas.
LSPLabel Switched Path: el camino etiquetado de entrada a salida. Es de un solo sentido.
LDPLabel Distribution Protocol: protocolo con el que los LSR se anuncian las etiquetas.
LIB / LFIBLIB guarda todas las etiquetas conocidas; LFIB solo las que se usan para reenviar.

LSP

El camino etiquetado es de un solo sentido

Un LSP (Label Switched Path) es la secuencia de LSR que sigue un paquete etiquetado hacia un prefijo. El retorno usa otro LSP, con otras etiquetas, aunque normalmente pase por los mismos routers porque el IGP es simétrico.

PHP

El penúltimo salto quita la etiqueta

Sin PHP, R5 busca en la LFIB, ve que no hay etiqueta de salida, la quita y vuelve a buscar en la FIB. Con PHP, R5 anuncia la etiqueta especial 3 (implicit-null): R4 entiende que debe quitarla y enviar el paquete IP limpio.

Sin PHP: dos búsquedas en R5

R4# show mpls forwarding-table 10.0.0.0 Local Outgoing Prefix Bytes Outgoing Next Hop Label Label or Tunnel Id Switched interface 65 23 10.0.0.0/24 0 Gi0/1 10.45.0.5 R5# show mpls forwarding-table 10.0.0.0 Local Outgoing Prefix Bytes Outgoing Next Hop Label Label or Tunnel Id Switched interface 23 No Label 10.0.0.0/24 0 Gi0/2 10.0.0.1

R5 recibe la etiqueta 23, la quita (LFIB) y luego busca 10.0.0.0/24 en la FIB.

Con PHP: una búsqueda en R5

R4# show mpls forwarding-table 10.0.0.0 Local Outgoing Prefix Bytes Outgoing Next Hop Label Label or Tunnel Id Switched interface 65 Pop Label 10.0.0.0/24 0 Gi0/1 10.45.0.5 R5# show mpls ldp bindings 10.0.0.0 24 lib entry: 10.0.0.0/24, rev 12 local binding: label: imp-null remote binding: lsr: 4.4.4.4:0, label: 65

R5 anuncia imp-null para sus redes conectadas. Es el comportamiento por defecto en IOS.

Implementación de MPLS · paso 1

Sin CEF no hay MPLS

MPLS usa la FIB de CEF para saber qué etiqueta imponer. CEF se activa de forma global y queda activo en todas las interfaces que lo soportan.

ip cef [distributed]

  • Modo de configuración global. Inicia CEF y crea la FIB.
  • distributed activa dCEF, que corre en las tarjetas de línea (VIP).
  • Todas las interfaces compatibles quedan con CEF.

ip route-cache cef

  • Modo interfaz. Activa CEF en una interfaz en particular.
  • Casi nunca hace falta: con el comando global ya está activo.
  • no ip route-cache cef lo desactiva en esa interfaz.

mpls label range 16 1000

Opcional. Limita el rango de etiquetas que asigna el router, por ejemplo para reconocer de un vistazo qué router asignó cada etiqueta en un laboratorio.

R1# show ip cef summary IPv4 CEF is enabled and running VRF Default 23 prefixes (23/0 fwd/non-fwd) R1# show cef interface Gi0/1 | include switching IP CEF switching enabled R1# show mpls label range Downstream Generic label region: Min/Max label: 16/1000
Si show ip cef responde %IPv4 CEF not running, ningún paquete se etiqueta aunque LDP esté arriba. Es lo primero que se revisa.
Implementación de MPLS · paso 2

Activar MPLS en cada interfaz del núcleo

Router(config-if)# mpls ip ! activa la conmutación de etiquetas en la ! interfaz e inicia LDP Router(config-if)# mpls label protocol [tdp | ldp | both] ! elige el protocolo de distribución
Actualización. TDP es el protocolo antiguo de Cisco y ya no existe en IOS actual. Desde IOS 12.4(3) el valor por defecto es LDP, y en IOS-XE solo queda LDP. Las opciones tdp y both se explican porque aparecen en el original y en redes heredadas.

Lo que hacen los dos

  • Asignan una etiqueta a cada prefijo que eligió el IGP.
  • Descubren vecinos, abren, supervisan y cierran sesiones.
  • Distribuyen, solicitan y liberan asociaciones etiqueta-prefijo.
  • Construyen los LSP que usan los servicios del proveedor, como las VPN.

Configuración de MTU

Cada etiqueta suma 4 bytes al paquete

Un paquete IP de 1500 bytes con etiquetas ya no cabe en una MTU LAN de 1500. Para no fragmentar, se sube la MTU MPLS en todos los routers del segmento y se activan jumbo frames en los switches del camino. Elige el servicio.

Resumen

Lo que hay que llevarse

La idea

  • Se clasifica en el borde una vez; el núcleo reenvía solo por etiqueta.
  • Push en la entrada, swap en el núcleo, pop a la salida.
  • El LSP es unidireccional.
  • MPLS es la base de VPN de capa 3, capa 2 y TE.

Etiquetas y LDP

  • Cabecera de 32 bits: Label 20, EXP/TC 3, S 1, TTL 8.
  • LDP: Hello UDP 646 a 224.0.0.2, sesión TCP 646 hacia el LDP ID.
  • LIB guarda todas; LFIB, la del siguiente salto del IGP.
  • PHP: el egreso anuncia imp-null (3) y el penúltimo salto quita la etiqueta.

Implementación

  • ip cef primero.
  • mpls ip en cada interfaz interna; LDP por defecto.
  • Bloquear UDP/TCP 646 hacia los clientes.
  • MTU: 1500 + 4 bytes por etiqueta.

Diagnóstico

  • De abajo hacia arriba: IGP, CEF, interfaces, LDP, LFIB.
  • Loopbacks /32 de los routers de borde en el IGP, sin resumir.
  • Hellos sin sesión: LDP ID inalcanzable o TCP 646 bloqueado.
  • traceroute muestra la etiqueta en cada salto.
