Introducción a MPLS

Reenviar por etiqueta en vez de por dirección IP

MPLS (Multiprotocol Label Switching) decide el reenvío con una etiqueta corta. Solo los routers de borde miran la IP; el núcleo cambia una etiqueta por otra.

Qué aporta

  • Menos trabajo en el núcleo: buscar una etiqueta es más simple que buscar el prefijo más largo.
  • Independiente del protocolo de capa 3: sirve para IPv4, IPv6 y tramas de capa 2.
  • Es la base de las VPN de capa 3, las de capa 2 y la ingeniería de tráfico.
MPLS no es mucho más rápido que el enrutamiento IP actual con CEF. Su valor está en los servicios que permite construir encima.

LSP

El camino etiquetado es de un solo sentido

Un LSP (Label Switched Path) es la secuencia de LSR que sigue un paquete etiquetado hacia un prefijo. El retorno usa otro LSP, con otras etiquetas, aunque normalmente pase por los mismos routers porque el IGP es simétrico.

La sesión TCP va a la dirección del LDP ID. Si esa loopback no está en el IGP, hay Hellos pero nunca hay sesión. Fíjala con mpls ldp router-id Loopback0 force.

PHP

El penúltimo salto quita la etiqueta

Sin PHP, R5 busca en la LFIB, ve que no hay etiqueta de salida, la quita y vuelve a buscar en la FIB. Con PHP, R5 anuncia la etiqueta especial 3 (implicit-null): R4 entiende que debe quitarla y enviar el paquete IP limpio.

Sin PHP: dos búsquedas en R5

R4# show mpls forwarding-table 10.0.0.0 Local Outgoing Prefix Bytes Outgoing Next Hop Label Label or Tunnel Id Switched interface 65 23 10.0.0.0/24 0 Gi0/1 10.45.0.5 R5# show mpls forwarding-table 10.0.0.0 Local Outgoing Prefix Bytes Outgoing Next Hop Label Label or Tunnel Id Switched interface 23 No Label 10.0.0.0/24 0 Gi0/2 10.0.0.1

R5 recibe la etiqueta 23, la quita (LFIB) y luego busca 10.0.0.0/24 en la FIB.

Con PHP: una búsqueda en R5

R4# show mpls forwarding-table 10.0.0.0 Local Outgoing Prefix Bytes Outgoing Next Hop Label Label or Tunnel Id Switched interface 65 Pop Label 10.0.0.0/24 0 Gi0/1 10.45.0.5 R5# show mpls ldp bindings 10.0.0.0 24 lib entry: 10.0.0.0/24, rev 12 local binding: label: imp-null remote binding: lsr: 4.4.4.4:0, label: 65

R5 anuncia imp-null para sus redes conectadas. Es el comportamiento por defecto en IOS.

Dirección VPNv4

El RD hace único un prefijo repetido

Los clientes A y B pueden usar las mismas redes. El PE antepone a cada prefijo el Route Distinguisher (8 bytes) de la VRF y obtiene una dirección VPNv4 de 12 bytes. Elige cliente y prefijo.

RD: 8 bytes (ASN:número o IP:número)IPv4: 4 bytes
Lo que falta en el original. El RD solo hace única la ruta. Lo que decide en qué VRF se instala es el Route Target (RT): el PE exporta con route-target export y el PE remoto importa con route-target import. Si el RT no calza, la ruta llega por MP-BGP pero no aparece en la VRF.

Resumen

Lo que hay que llevarse

Operación de MPLS

  • Los PE (LSR de borde) ponen y quitan etiquetas; los P las cambian.
  • LDP: Hello UDP 646, sesión TCP 646 hacia el LDP ID.
  • El LSP es unidireccional.
  • PHP: el penúltimo salto quita la etiqueta (imp-null).

VPN de capa 3

  • Una VRF por cliente en cada PE.
  • Los CE no saben nada de MPLS.
  • RD + IPv4 = VPNv4, intercambiada por MP-BGP entre PE.
  • El RT decide en qué VRF se importa.

Diagnóstico

  • Abajo hacia arriba: IGP, LDP, LFIB, MP-BGP, VRF.
  • Loopbacks /32 de los PE en el IGP.
  • Pila: etiqueta VPN adentro, LDP afuera.
  • Prueba con ping vrf y traceroute vrf.
