Listas de acceso IPv4

De arriba hacia abajo, gana la primera coincidencia

Elige un paquete y evalúalo contra la ACL 100. Mira en qué línea se detiene y qué pasa si ninguna coincide.

1. Procesamiento descendenteLas entradas se revisan en orden, desde la de menor número de secuencia.
2. Ejecución inmediataLa primera entrada que coincide decide: permit o deny. Las demás ya no se miran.
3. Deny implícitoAl final hay un deny any invisible. Una ACL sin ningún permit lo bloquea todo.

Listas de acceso IPv4

Una entrada que se activa según el reloj del router

La entrada 10 bloquea la web de 10.1.1.5 solo fuera del horario laboral. Mueve el día y la hora para ver cuándo está active.

El router usa su propio reloj. Si la hora está mal (sin NTP o con zona horaria errada), la ACL se activa en otro momento. Revisa show clock y show ntp status.
Listas de acceso IPv6

IPv6 agrega dos permisos implícitos antes del deny final

Neighbor Discovery (NDP) reemplaza a ARP. Para que no se rompa, cada ACL IPv6 permite NA y NS de forma implícita. Agrega la línea de abajo y mira el efecto.

Fe de erratas. La presentación original escribe deny ipv6 any aní log; el comando es deny ipv6 any any log.

Con las reglas implícitas, NS y NA pasan aunque no las escribas.

Control Plane Policing

CoPP limita el tráfico que llega a la CPU del router

Es una política de QoS aplicada a la interfaz lógica control-plane. Clasifica el tráfico hacia la CPU (gestión, enrutamiento, ICMP…) y le pone un límite de velocidad a cada clase, para que una ráfaga inesperada no desestabilice el equipo.

conform

Dentro de la tasa. Normalmente transmit.

exceed

Sobre la tasa, dentro de la ráfaga extra. Se decide transmit o drop.

violate

Muy por sobre la tasa. Al principio conviene transmit para medir y ajustar sin cortar nada.

Fe de erratas. El resumen original dice que CoPP se basa en el firewall por zonas (ZBF). En realidad usa MQC, la misma estructura de QoS: class-map, policy-map y service-policy.
CoPP · paso 1

Las ACL definen qué protocolos caen en cada clase

Aquí permit no significa “dejar pasar”: significa “esto pertenece a la clase”. Son ACL abiertas; el control lo hace el policer.

ip access-list extended ACL-CoPP-ICMP permit icmp any any echo-reply permit icmp any any ttl-exceeded permit icmp any any unreachable permit icmp any any echo permit udp any any range 33434 33463 ttl eq 1 ! ip access-list extended ACL-CoPP-IPsec permit esp any any permit gre any any permit udp any eq isakmp any eq isakmp permit udp any any eq non500-isakmp permit udp any eq non500-isakmp any ! ip access-list extended ACL-CoPP-Initialize permit udp any eq bootps any eq bootpc
ip access-list extended ACL-CoPP-Management permit udp any eq ntp any permit udp any any eq snmp permit tcp any any eq 22 permit tcp any eq 22 any established ! ip access-list extended ACL-CoPP-Routing permit tcp any eq bgp any established permit eigrp any host 224.0.0.10 permit ospf any host 224.0.0.5 permit ospf any host 224.0.0.6 permit pim any host 224.0.0.13 permit igmp any any

Qué revisar en estas ACL

  • Agrupamiento: una clase por función (enrutamiento, gestión…). Mezclar protocolos impide darles tasas distintas.
  • Protocolo: si es el incorrecto, el tráfico cae en otra clase.
  • Origen y destino: si se restringen, deben ser los correctos.
  • Operadores y puertos: eq, range, gt con el número correcto.
El tráfico se identificó antes con EPC (Embedded Packet Capture), que captura en el propio router lo que llega al plano de control.

match-all o match-any

Qué revisar en el class-map

Grupo de accesoLa ACL del match define el tráfico interesante. Si está mal, la clase queda vacía.
Instrucciónmatch-any: basta un match. match-all: deben cumplirse todos.
ProtocoloSin ACL se puede usar match protocol; verifica que sea el correcto.
Prec / DSCPmatch ip precedence o match ip dscp para clasificar por marca.
MayúsculasEl nombre de la ACL debe coincidir exacto: ACL-CoPP-icmp no es ACL-CoPP-ICMP.
CoPP · paso 3

El policy-map pone la tasa y la acción de cada clase

Las clases vitales (IPsec, gestión, enrutamiento) usan violate-action transmit mientras se mide una línea base. ICMP, DHCP y el resto se descartan al violar.

policy-map POLICY-CoPP class CLASS-CoPP-ICMP police 8000 conform-action transmit exceed-action transmit violate-action drop class CLASS-CoPP-IPsec police 64000 conform-action transmit exceed-action transmit violate-action transmit class CLASS-CoPP-Initialize police 8000 conform-action transmit exceed-action transmit violate-action drop class CLASS-CoPP-Management police 32000 conform-action transmit exceed-action transmit violate-action transmit class CLASS-CoPP-Routing police 64000 conform-action transmit exceed-action transmit violate-action transmit class class-default police 8000 conform-action transmit exceed-action transmit violate-action drop

Qué revisar en el policy-map

OrdenLas clases se evalúan de arriba hacia abajo; un paquete queda en la primera que coincide.
Class-mapCada class debe existir y estar bien construido, con su ACL correcta.
PolíticaCIR en bits por segundo (police 8000) o tasa en paquetes por segundo (police rate … pps). Confundirlos cambia la tasa por mucho.
class-defaultTodo lo que no calza cae aquí. Si su tasa es baja, protocolos olvidados en las ACL sufren descartes.
MayúsculasEl nombre del class-map debe coincidir exacto.

Troubleshooting CoPP

Del síntoma a la causa

Introducción a Service Provider

VRF-Lite: varias tablas de enrutamiento en un mismo router

Una VRF (Virtual Routing and Forwarding) es una tabla de enrutamiento independiente. En un proveedor se usa con MPLS, una por cliente. VRF-Lite es usar VRF sin MPLS: el router Central separa a VRF A de VRF B aunque compartan el equipo.

Qué consigue

  • Cada VRF tiene sus propias rutas, interfaces y vecinos.
  • Pueden repetirse prefijos entre VRF sin conflicto.
  • No hay tráfico entre VRF salvo que se configure a propósito.
Cada interfaz pertenece a una sola VRF. Para llevar varias VRF por un mismo enlace hacen falta subinterfaces, una por VRF. Ese es el costo que EVN reduce.
VRF-Lite

Crear la VRF, asociar la interfaz y mirar la tabla correcta

Cambia de tabla. La global de Central no tiene ninguna de estas redes: si buscas con show ip route sin vrf, parece que no existen.

Central(config)# ip vrf VRF-A Central(config)# ip vrf VRF-B Central(config)# interface Serial0/0/0 Central(config-if)# ip vrf forwarding VRF-A Central(config-if)# ip address 10.10.1.1 255.255.255.252 Central(config)# interface Serial0/0/1 Central(config-if)# ip vrf forwarding VRF-A Central(config-if)# ip address 10.20.2.1 255.255.255.252 Central(config)# interface Serial0/1/0 Central(config-if)# ip vrf forwarding VRF-B Central(config-if)# ip address 10.30.3.1 255.255.255.252 ! … Serial0/1/1 igual, en VRF-B con 10.40.4.1/30
ip vrf forwarding borra la IP que ya tenía la interfaz (% Interface … IPv4 disabled and address(es) removed). Por eso se escribe antes de ip address. Si se hace al revés, la interfaz queda sin IP.

Comandos con contexto de VRF

show ip route vrf VRF-A · ping vrf VRF-A 10.10.1.2 · show ip vrf interfaces · router ospf 1 vrf VRF-A

EVN

EVN: un solo troncal virtual en vez de una subinterfaz por VRF

Cisco Easy Virtual Network se apoya en VRF-Lite. Entre routers usa un VNET trunk que etiqueta cada VRF con un vnet tag, así la configuración no crece con el número de VRF.

  • Interfaces de borde: hacia los usuarios, 802.1Q normal, una VLAN por VRF.
  • Interfaz troncal: entre routers EVN, vnet trunk transporta todas las VRF.
EVN

Servicios compartidos sin BGP y diagnóstico por contexto

Replicación de rutas

DHCP, DNS y correo viven en la VRF C. Con route replication, VRF A y VRF B ven las rutas de C sin ver las de la otra. Antes esto exigía importar rutas con BGP, route distinguisher y route targets.

vrf definition A address-family ipv4 route-replicate from vrf C unicast connected

routing-context

Entra al contexto de una VRF y desde ahí los comandos se aplican a esa VRF sin escribir vrf cada vez. El prompt lo muestra.

R1# routing-context vrf red R1%red# show ip route ! muestra la tabla de la VRF red R1%red# routing-context vrf global R1#
EVN existe solo en ciertas plataformas IOS-XE (por ejemplo, Catalyst 4500/6500 y ASR 1000). Si el comando vnet no aparece, el equipo no lo soporta.
Resumen

Lo que hay que llevarse

ACL IPv4

  • De arriba abajo, primera coincidencia, deny implícito.
  • Revisa contadores con show access-lists.
  • Interfaz y sentido: show ip interface.
  • Las de tiempo dependen del reloj.

ACL IPv6

  • Solo extendidas y nombradas.
  • Permiten NA y NS de forma implícita.
  • Un deny ipv6 any any explícito rompe NDP.
  • ipv6 traffic-filter.

CoPP

  • MQC: ACL → class-map → policy-map → control-plane.
  • Orden de clases y class-default.
  • bps frente a pps.
  • Nombres exactos en cada paso.

VRF-Lite y EVN

  • Tablas separadas sin MPLS.
  • ip vrf forwarding antes de la IP.
  • Busca siempre con vrf.
  • EVN: vnet trunk y route replication.
